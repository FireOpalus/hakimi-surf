# v1.3.1：高清图片、超长图切片与图片限制热配置

[架构图](../architecture.html#image-context) 按当前 `media.py`、`service.py` 和管理配置链路更新。保留 v1.2.0 的图片来源选择、隔离缓存和 ACK 摘要闭环，以及 v1.3.0 的休息门禁、图片消费去重与短续链。

## 接收与处理

原图限制先于解码与模型调用：消息／RPC 声明的大小、Base64 解码后的实际大小、HTTP 响应长度与流式累计字节都受检查。默认允许 16 MiB、50 MP；应用字节硬上限为 20 MiB，像素配置最大为 80 MP，超限降级占位。

取图依次尝试 NapCat `get_image`、`get_file` 返回的 Base64，再使用受限 QQ CDN。WS 取图全局串行，每个 RPC 最长 15 秒；HTTP 单次最长 12 秒、连接超时 5 秒，仅既有两类 QQ CDN 可在指定错误后降级 HTTP 一次。下载批次最多并行两组，解码通过单独信号量和 `asyncio.to_thread` 串行执行。

这些是应用图片限制；OneBot WS 仍有独立的 16 MiB 帧上限。Base64 及 JSON 占用额外帧空间，因此允许 16 MiB 原图不等于 WS 能直接承载同样大小的原始文件。此次未修改部署端口、帧上限或跨机拓扑。

| 类型 | 默认缩放与模型分辨率 |
| --- | --- |
| 常规静态图，长宽比 ≤ 2.2 | 长边 ≤ 1600 px、短边 ≤ 1200 px；原始长边 ≥ 1200 px 使用 `high`，否则 `medium` |
| 长截图，长宽比 > 2.2 | 长边 ≤ 2560 px、短边 ≤ 1080 px，使用 `high` |
| 动图 | 首尾各取一帧并拼接，整体缩至 1152×768 范围，使用 `medium`；最多 300 帧、帧数 × 原始像素 ≤ 6400 万 |

均使用 Lanczos、保持比例且不放大。先应用 EXIF 方向，输出清除元数据；满足条件的大 JPEG 使用 `draft()` 降低解码尺寸。普通／长图 JPEG 初始质量为 85／86，优先保留颜色细节；动图初始质量 82。编码会尝试 78、72、65 等质量档，目标 ≤ 800 KiB；若所有尝试仍超出，返回其中最小结果，因此 **800 KiB 是压缩目标，不是硬性输出上限**。门卫继续使用低分辨率缩略图：常规图长边 448 px，长图及切片 512 px。

## 超长图占用两个现有槽位

静态图长宽比 > 4.5 且长边超过长图配置上限时，沿长轴切成两片，交界保留约 32–96 px 重叠；横长图左右切，竖长图上下切。每片仍按长图尺寸缩放，同时保留整图概览。

`Service.message_images()` 仅在本批加载结果中恰有一张成功图片、且至少有两个可用模型槽位时启用双切片。两片都标注同一发送者和来源，并分别标记 `slice=1/2`、`2/2`；来源消息只登记一次。若另有成功图片，或只剩一个槽位，使用整图概览。每轮模型图片总数仍不超过两张，切片不绕过来源筛查和预算预留。

## 缓存与管理控制

缓存键包含会话 scope、原始内容摘要和普通／长图两个尺寸。后续常规加载发现尺寸不同会重新处理，不复用旧尺寸的缓存结果；字节／像素限制不是缓存键，不会主动清除已解码内容。缓存内存核算覆盖整图、缩略图、两片及其缩略图，继续受总量 48 MiB、每会话 30 项、全局 1024 项约束，别名另限 4096 项。

`/admin` 的“回复与联网”新增“图片尺寸与智能压缩”，复用 ADMIN_TOKEN、同源检查和配置写入锁：

| 配置 | 默认值 | 后台 API 范围 |
| --- | --- | --- |
| `image_max_bytes` | 16,777,216 | 1–20 MiB，整数 Byte |
| `image_max_pixels` | 50,000,000 | 65,536–80,000,000，整数像素；页面以 MP 输入 |
| `image_standard_max_edge` | 1600 | 512–2560 px |
| `image_tall_max_edge` | 2560 | 1024–4096 px，且不得小于普通图长边 |

对应 `.env` 项均带 `HAKIMI_` 前缀。`GET /admin/api/image-limits` 返回当前值、启动初始值和来源；`PUT` 验证后加密写入现有 `admin_config.image_limits` 并同步应用；`DELETE` 删除覆盖并恢复启动时 `.env` 初始值。无需新增 SQLite 表。

兼容初始化仅在没有管理员图片覆盖、启动值恰为旧默认 4 MiB／12 MP、已有账本记录且未标记升级时，将四项默认值保存为新的管理员覆盖。沿用代码中的一次性标记 `meta.image_limits_v140`；它是兼容键名，不代表本次发布版本。自定义配置和已有管理员覆盖保留，原账目及会话数据不改写。

本次交付只更新源码与文档并推送 GitHub，不执行部署，也不对生产数据库运行初始化。
