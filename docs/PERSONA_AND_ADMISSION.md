# 0.6.1：原文人设与群／私聊准入解耦

`persona.py` 集中保存用户提供的三段原文：`SYSTEM_INSTRUCTION`、`PUBLIC_PERSONA_PROMPT`、`OWNER_PERSONA_PROMPT`。正文、Markdown 标记、空格和标点均保持原样，没有追加旧的人设动作描写或能力说明。

Interactions 每轮的系统指令顺序为：

1. 共享 `SYSTEM_INSTRUCTION`；
2. 根据服务器验证的身份选出的 PUBLIC 或 OWNER 差异段；
3. 原有业务场景指令；
4. 服务器生成的可信角色、场景与隐私约束。

事实摘要压缩保留原有独立分支：共享指令后接压缩指令，不加载 Owner 人设。全部九个生成场景都以共享指令开始。模型版本、Decisions 网关、分档、预算、`store=False`、空工具列表以及动态身份构造保持原有逻辑。

## 准入规则

| 来信 | 准入与互动 |
| --- | --- |
| 白名单群中的普通群友 | 无论是否在私聊好友名单，都可按群策略互动 |
| 不在白名单中的群，或 `muted` 群 | 前置静默忽略 |
| Bot 自身、外部机器人黑名单、小黑屋用户 | 在模型和素材请求前忽略 |
| 真实 Owner 私聊 | 固定允许，使用 OWNER 人设 |
| 普通好友私聊 | 仅在 `owner_and_allowlist` 模式且属于好友白名单时允许，使用 PUBLIC 人设 |
| 陌生人私聊 | 前置静默忽略；不会因为曾在获准群聊天而获得私聊权限 |

群策略仍独立决定何时回应：`at_only` 响应明确点名、已核验引用或视频请求；`smart_reply` 判断自然插话；`muted` 不回应。新增群成员权限不会修改任何群的策略、准入名单或黑名单，也不意味着每条普通发言必回。

`HAKIMI_ALLOW_GROUP_MEMBERS` 仅为兼容旧 `.env` 保留，即使为 `false` 也不再限制白名单群的成员。后台「准入与防互刷名单」显示实际生效的新规则；私聊名单只用于私聊。

## Owner 边界

只有已认证 OneBot 事件中的机器人 Self-ID 与配置一致、并且真实 `user_id == OWNER_QQ_ID`，才能获得 Owner 身份。群聊 Owner 依然使用公开人设；专属人设与快照必须同时满足本人私聊条件。普通群友无法通过昵称、正文、引用或模型判断获得管理权限。

旧 `HAKIMI_ONEBOT_OWNER_IDS` 与 `HAKIMI_QQ_OWNER_IDS` 不再授予管理权限。官方 QQ OpenID 无法证明数字 QQ Owner 身份；该平台的普通私聊需显式配置 `HAKIMI_QQ_ALLOWED_USERS`，只使用公开人设。群上下文重置、记忆开关等管理命令同样锁定真实 Owner。管理后台仍由独立的 `ADMIN_TOKEN` 保护。

所有群会话、普通好友私聊和 Owner 私聊继续使用各自的 SQLite 数据库；本次升级不会清空已有会话、滚动摘要或预算账本。小本本开关、Drive 授权与其他后台设置保持原值。

## 验收方式

通过现有 SSH 隧道访问 `http://127.0.0.1:12141/admin`。在群白名单中保留测试群，让一名不在私聊白名单中的普通群友在群里明确 @ Bot；应按群策略正常响应。同一个账号私聊 Bot，若未被私聊模式和好友名单放行，应静默忽略。黑名单账号在该群中仍不会触发模型调用。

原文校验测试使用独立计算的摘要值；SDK Mock 测试验证真实序列化请求中的提示词顺序与身份隔离。服务集成测试覆盖空私聊名单、仅 Owner 名单、两种私聊模式、`at_only`／`smart_reply`、旧开关为 false、黑名单零 API 消耗以及 Owner 私密记忆不进入普通群回复。测试不会调用付费 Gemini 或操作真实 QQ 账号。
