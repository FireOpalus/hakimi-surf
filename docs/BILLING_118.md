# v1.1.8：缓存折扣结算与中断费用估算

[架构图](../architecture.html#billing) 将一次付费调用分为事务预留、供应商请求、结算与聚合四个阶段。模型路由、A/B/C 前缀、Bot 接话阈值、双轨记忆、ACK 投递和跨机部署沿用现有实现。

## 预留与结算

调用前仍按完整逻辑上下文的 UTF-8 字节、媒体预算与输出上限预留，在 SQLite 事务中检查全局日／月／总预算、用户及分项额度。差量续链不缩小这项预留。

返回有效 usage 后，按配置费率计算输入、输出与思考费用；已报告的缓存输入应用缓存费率，联网请求另计已报告的查询费。缓存折扣现在直接进入 `ledger.amount`，并释放多余预留，同时更新总预算、日／月／累计及按模型聚合。`memory_flex` 在日历账本重建时也计入 Interactions 缓存观测。

费用是本地根据 usage 与配置价格计算的估算，不是从 Google 账单 API 读取的实扣金额。缺失缓存字段仍保持未知，不补造命中量；未报告缓存时不应用缓存折扣。价格配置、工具费用及供应商最终账单仍需独立核对。

## 异常与取消分支

| 情况 | 本地结算行为 |
| --- | --- |
| 请求发出前撤销／取消 | 释放预留，记 0 |
| 尚未收到流事件，HTTP 状态为 400／401／403／404／409／413／422／429 | 按当前实现的未计费错误策略，释放预留，记 0；不是对所有 4xx 一概退款 |
| 超时、发出后取消、流中断、其他含糊错误或缺少完整 usage／工具费用 | 保留 `unknown` 状态，用有上界的回退费用计入预算；不把未知当免费 |
| 进程崩溃、未取得回退信息的在途预留 | 重启恢复时保留预留金额并标记未知，不自动重发 |
| 结算金额超过预留 | 保留既有持久化超支熔断 |

`StreamProgress` 跟踪请求是否发出、是否已收到事件及已收到的输出文本。回退估算优先使用可用的 usage；否则采用本地文本 Token 估算、媒体份额、流片段与耗时余量。差量续链仅在这个回退分支中估算已复用前缀的缓存份额。结果不超过预留，正预留下至少计 1 微美元，Token 明细与估算完整性仍标为未知。

这些回退数据无法证明供应商实际生成了多少内容，可能高于或低于最终账单。部分输出不会发送给用户；既有超时／不完整响应降档重试仍最多一次，每次独立预留。

## 历史账本一次性校正

启动时 `_reconcile_bill_aligned_v1()` 在事务内读取保留的非 `reserved` 明细：已有合法折后金额的已结算行改用该金额；符合条件的已结算行补齐费用估算；金额仍等于全额预留的已归属未知生成行按现有启发式收敛。未知行仍保持 `unknown`，不会补造 Token 或 Google 账单证据。

迁移同步调整 `budget_totals`、`usage_aggregates` 与 `model_usage_aggregates`，完成后写入 `meta.bill_aligned_v1`。再次启动不重复校正；已清理、无法逐条恢复的历史保留原聚合金额。不清空账本、不改变预算上限，也不重建隔离会话。升级前备份完整数据卷；若需要恢复旧费用口径，应使用配套的升级前数据库备份，单独回退镜像不会撤销迁移。

## 管理台与发布验证

管理台费用标签同步为结算估算与预算占用，仍区分已知与未知 usage、缓存覆盖率及历史未归属调用。Google Drive 同步不计入 Gemini 账本。

本版发布检查覆盖缓存折扣、错误／取消结算、搜索工具费、事务预算与日历聚合，以及生产数据库副本连续两次初始化。容器冒烟使用本地协议模拟器与模拟凭证，不调用付费模型；上线只读核对配置、版本、鉴权、健康状态与 WSS 心跳。
