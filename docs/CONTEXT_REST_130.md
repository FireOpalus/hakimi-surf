# v1.3.0：续链尾窗去重、休息时段与思考档位账本

[架构图](../architecture.html) 新增 [休息门禁](../architecture.html#rest-hours) 与 [思考档位归账](../architecture.html#thinking-accounting)，更新续链、图片消费及冷历史退避流程。跨机 OneBot、身份隔离、预算预留、ACK 入史和 v1.1.8 费用口径继续沿用。

## A / B / C 与短续链

首次请求使用 A 静态指令、完整 B 热史与完整 C 尾窗；有效续链每轮仍传 A，只发送未覆盖的 ΔB，并压缩 C：

- 保留当前时间、可信身份、当前批次与必要的非空权限／媒体／搜索字段。
- 对滚动摘要、Owner 只读背景、双轨召回及表情标签计算摘要，省略与上一条已确认链状态相同的非空内容。表情名单变为空时仍发送空列表。
- 邻近消息按内容摘要去重，已见摘要窗口最多 16 项。首次起链或重新起链恢复完整当前上下文。

链状态新增 `turns`、`context_digests`、`seen_nearby`，随 Outbox 候选在 ACK 后加密提交。新提交链的默认有效期由 6 小时改为 300 秒，仍可用 `HAKIMI_INTERACTION_CHAIN_TTL_SECONDS` 覆盖；每条链最多 12 轮，第 13 轮从完整本地上下文重新起链。旧载荷缺失新字段时使用兼容默认值，不清空聊天记忆。

节省的是实际发送载荷；预算仍按完整逻辑上下文预留。云端留存期限不等于本地链有效期。有效缓存观测在空闲超过 180 秒、思考档位或原有标记变化后重新建立样本，不将这些轮次直接当作异常击穿；这不等于承诺缓存命中。

## 图片消费与弃权

自动补充邻近图片时，排除 B 热史、当前批次、已有视觉摘要及 `group_consumed_images` 记录中的事件。成功发送／ACK 后才写入消费记录，未确认投递不提前消费；记录按群会话隔离、保留 300 秒，重置会话时清除。明确要求再看旧图仍可以走 v1.2.0 的受限 HotRing 找图路径。

聊天模型返回合法 `abstain=true` 时，先规范化为空气泡、空引用／点名、空贴纸、无视觉摘要；不调用输出门卫，不发送、不提交新的续链候选。生成请求本身仍正常计费。非弃权内容继续进行输出筛查。门卫已记录的拦截通过 `Rejected.audited` 避免上层重复写同一条告警，业务计数和决策审计继续更新。

## 每日休息时段

默认 `REST_HOURS_ENABLED=true`、`REST_HOURS=23:00-08:00`、`REST_ALLOW_OWNER_PRIVATE=false`，按 `BOT_TIMEZONE` 判断，起点包含、终点不包含，支持跨午夜。当前版本在「世界引擎 → 睡眠与白天小憩」编辑时间与 Owner 私聊例外。设置经 `/admin/api/life/rest-hours` 加密保存，原 `/admin/api/rest-hours` 入口兼容已有客户端。

| 入口 | 休息期间行为 |
| --- | --- |
| 新入站群聊／私聊 | 基础解析和隔离接收日志后停止，不入模型工作队列，不主动水合图片／网页；保留允许的群聊被动背景及撤回处理 |
| Owner 私聊例外 | 仅开启 `allow_owner_private` 且协议确认真实 Owner 私聊时放行；群内 Owner 不适用 |
| 已排队、尚未到模型的聊天 | 处理开始和门卫前复检；不强制取消已经发出的模型调用或投递 |
| 定时订阅巡逻与 B 站小号 `tick()` | 暂停；后台显式手动执行仍按自身权限、预算与风控规则运行 |
| 主动陪伴 | 计划避开休息及原有免打扰时段，发送前再次检查，待发问候到边界过期；修改作息只重排未尝试计划 |
| 运维模板告警、日报、Drive 同步、记忆归档、后台管理／沙箱 | 不被这个新增开关统一暂停，继续服从各自配置与预算 |

休息期收到的聊天不会在结束后统一补发。休息并不等于关闭所有后台付费任务；若要停用某项后台功能，应修改对应开关或预算。

## 思考档位账本与审计

每次预留就保存请求下发的 `model_lane` 和 `thinking_level`；结算、取消、失败与重启恢复继续使用该归属。账本增加模型 × 档位明细及跨模型档位汇总，按今日／本月／累计展示调用次数、Token 与费用。档位是请求参数，不能据此反推模型实际进行了多少思考；思考 Token 仍取供应商 usage。

Decisions 标为 `none`，搜索和 memory Flex 使用固定 `medium`，普通聊天记录 auto 路由或后台覆盖后实际发送的档位。决策审计补记生成尝试最后使用的模型通道与档位；发生降档重试时，账本仍分别保留每次请求。

首次启动仅从保留的非 reserved 旧明细回填：已知 Decisions 为 `none`，其他未记录档位的旧调用为 `unknown`，不推测历史档位，也不重建已清理的明细。因此旧档位统计覆盖范围可能小于累计模型统计。迁移标记 `meta.thinking_usage_v1` 保证重复启动不重复归账；原有账目金额不改写。

## Flex 429 与兼容升级

生产环境的记忆 Flex 使用独立、按 `memory_flex_timeout` 配置的 v1 客户端。未进入流、可判定为未计费的 429 返回 `rate_limited` 详情；压缩器将已领取批次退回 pending，后台分别等待 60／120 秒，最多安排两次额外尝试，成功后清除退避。普通含糊失败不借此无限重试。

退避计数是当前进程最多 256 项的内存状态，重启或逐出会丢失，不能描述为跨重启的永久重试上限。每次模型请求仍独立预留，手动强制提炼可跳过后台等待，预算／供应商门禁继续有效。

新增主库表：

| 表 | 键与用途 |
| --- | --- |
| `group_consumed_images` | `(scope, event_id)` 主键与 `at` 时间戳，群内邻近图消费去重 |
| `ledger_thinking` | `id` 主键，保存模型通道和请求档位 |
| `thinking_usage_aggregates` | `(period, model_lane, thinking_level)` 主键，累计调用、费用及各类 Token |

休息配置复用加密 `admin_config`；续链新字段复用原加密载荷，隔离会话表不重建。源码交付包同时收录新增 `scripts/deploy_prod.sh`。本次发布仍先备份数据卷和凭证、检查目标镜像，再仅替换后端，保持协议端运行。
