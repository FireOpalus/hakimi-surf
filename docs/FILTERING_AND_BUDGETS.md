# 0.6.0：消息分流、过滤审计与预算

> 0.6.1 继续使用本文的网关、审计和账本规则，仅更新三段原文提示词及群／私聊准入解耦。新规则见 [人设与准入说明](PERSONA_AND_ADMISSION.md)；文末保留 0.6.0 验证记录。

这次升级保留 OneBot、会话物理隔离、Owner 私有人设、主动私信和双轨 B 站分析。无需新的依赖、OAuth 权限或 CDN。小本本继续默认关闭。

## 分流顺序

1. 本地验证平台身份、群／私聊准入、屏蔽用户与外部 Bot 黑名单。群号获准后，其所有非黑名单成员按本群互动策略处理，私聊名单和旧 `HAKIMI_ALLOW_GROUP_MEMBERS` 不再限制群员；私聊仍使用独立的收紧规则。不合格消息在 Gemini 调用之前丢弃。
2. 获准私聊，以及获准群中的真实 `@Bot`、直接文字呼唤「吉米奈喵／吉米奈／哈基米」、已核验的 Bot 引用回复、B 站链接／卡片，视为明确请求。它们只做消息安全检查，跳过 `should_reply`；仍受静默群策略、限流、预算与服务可用性约束。
3. `smart_reply` 的普通群聊先检查当前消息安全，再用另一轮仅包含 `should_reply` 的 Decisions 请求判断是否自然插话。第二轮参考同群最近最多 10 条脱敏短消息；每条最多 240 字，保留不超过 24 小时。历史只参与相关性判断，不能使当前用户被记违规。安全失败时不会继续判断插话。
4. 生成、外部来源和记忆压缩继续经过原有安全检查。放宽群聊消息阈值不会放宽视频、外链、快照或模型输出的门槛，也不授予任何模型执行权限。

引用核验使用本服务成功发送后的 OneBot `message_id` 回执，绑定机器人和具体群。回执只存 HMAC 索引，最多保留 7 天，重启可恢复。引用段自称的 `qq`、昵称、正文中的假角色不可信；没有回执的旧消息引用不会自动免除插话筛选。转发节点或分享卡片里的昵称不能伪装成直接点名。清空群 Session 同时清除该群的插话参考窗口。

## 后台与配置

通过 SSH 隧道打开 `http://127.0.0.1:12141/admin`，使用已有 `ADMIN_TOKEN` 登录。后台 API 沿用原有鉴权、同源和请求体限制；所有页面资源内嵌。

「过滤与审计」面板显示最近 30 次消息判定，包括群／私聊、脱敏节选、三个问题的实际分数与置信度、使用的阈值以及最终原因。没有调用的问题显示跳过，不伪造分数；失败记录不被显示成放行。节选加密存储，不进入日记或公开日志。

| 入站消息参数 | 默认值 |
| --- | --- |
| `HAKIMI_MESSAGE_INJECTION_THRESHOLD` | `0.78` |
| `HAKIMI_MESSAGE_UNSAFE_THRESHOLD` | `0.80` |
| `HAKIMI_MESSAGE_REPLY_THRESHOLD` | `0.42` |
| `HAKIMI_MESSAGE_OWNER_INJECTION_THRESHOLD` | `0.90` |
| `HAKIMI_MESSAGE_OWNER_UNSAFE_THRESHOLD` | `0.90` |

概率达到安全阈值才拦截；插话概率低于回复阈值才忽略。Owner 资格来自协议真实身份；群聊 Owner 仍使用公开人设。群活跃度可选全局默认、安静旁听 `0.65`、适中自然 `0.42`、活跃接梗 `0.28`。这些预设只影响自由插话，不覆盖群静默或准入名单。

真实 Owner 的群内自由发言沿用偏爱策略，插话阈值取当前群阈值与 `0.28` 中较小者；后台审计显示实际生效值。昵称或正文自称 Owner 无效。

旧 `HAKIMI_INJECTION_THRESHOLD=0.20`、`HAKIMI_UNSAFE_THRESHOLD=0.50` 用于外部来源和输出，保持独立。不要为了调整普通聊天而修改它们。后台热保存优先于环境变量，并在 SQLite 中加密持久化；可重置回 `.env` 初始值。

## Token 与费用

每次调用记录提供方返回的输入、输出、`total_cached_tokens` 和 `total_thought_tokens`。缺失字段为未知，不凭文本长度制造 token 使用记录。今日、本月、累计计数使用独立聚合表；清理历史逐次明细不会清零累计值。升级前缺失的缓存／思考数据无法追溯，后台会显示统计覆盖限制。

费用有两种口径：

- **实际估算**：未缓存输入按普通输入价，已缓存输入按缓存价，输出和思考按输出价计算。基于响应 usage 的本地估算，不替代 Google 账单。
- **保守熔断**：保持原有全价输入预留和结算，不预先假设缓存命中。失败或超时无法确认用量时保留预算占用，防止重试超支。后台分别展示已知实际估算与保守累计，未知数据不记成免费。

截至 2026-11-14，Hydrogen Standard 每百万 token 的普通输入为 $1.50、缓存输入为 $0.075、输出（含思考）为 $7.50。缓存价可由 `HAKIMI_CHAT_CACHED_INPUT_USD_PER_M` 配置。[Google 官方价格](https://aistudio.google.com/docs/pricing#gemini-4-hydrogen)

0.6.1 起，共享 `SYSTEM_INSTRUCTION` 始终放在 `system_instruction` 最前，随后是用户原文的公开／Owner 身份差异段、业务指令，最后才是服务器验证的当前角色标记。压缩场景保留共享指令加客观压缩指令的特例。不会在开头插入时间戳，也不改写三个提示词正文。Hydrogen 隐式缓存有最低输入长度等条件；短聊天命中率为 0 并不代表故障，不会为了命中而填充无用提示词。[Google 缓存说明](https://aistudio.google.com/docs/caching)

## 日／月预算

`HAKIMI_DAILY_USD=2`、`HAKIMI_MONTHLY_USD=40` 可在「Token 与预算账本」中直接修改，写入 SQLite 后立即生效。两者设为 `0` 都表示暂停付费调用，不表示无限额度。降低额度至已使用金额以下会阻止后续调用，已经发出的请求仍正常结算。

日预算按 UTC 日期，月预算按 UTC 自然月，沿用原账本日期口径。陪伴计划、日报及免打扰仍按 `BOT_TIMEZONE`。累计总限额、每用户限额、巡逻／后台／压缩／主动私信分项限额继续有效，最先达到的限制优先。提高日／月限额不会解除累计熔断；数据不因修改额度而重置。月预算同样接入 85%／100% 的本地零 Token 告警。

## SQLite 增量结构

- `ledger_usage`：与原 `ledger.id` 对应，存真实 token 观测、模型类型和实际估算费用；原账本结构保持兼容。
- `usage_aggregates`：UTC 日期、UTC 月份、累计三种范围的 token、调用覆盖和两种费用累计。
- `admin_config`：沿用加密配置表，增加 `filters` 与预算覆盖配置；不改变原准入名单。
- `decision_audit`：最近 30 条加密消息判定。
- `gateway_group_context`：按 HMAC 群 scope 隔离、限长、限时的加密插话参考。
- `sent_bot_receipts`：按群绑定的成功发送回执 HMAC 与时间，不保存消息正文。

启动时自动建表并迁移现存账本，重复启动不重复累计。保留升级前 `.env`、SQLite 在线备份和旧镜像即可回滚；不要换加密密钥或混用不同实例的数据目录。

## 验收

1. 登录后台，查看新过滤阈值、今日／累计缓存 Token 和日／月预算。没有历史 token 数据时应显示覆盖限制。
2. 在沙盒用普通群友明确 @、Owner 私聊和「测试／哈哈哈／猫娘叫一声」检查：显示 `should_reply` 跳过；真实攻击仍按安全分数处理。
3. 以普通群友普通发言测试自由插话；检查分数与最终原因。沙盒不读取或写入生产群聊窗口。
4. 修改阈值、某群活跃度、日／月预算，刷新页面确认保留；可用重置按钮恢复环境初始值。沙盒模型测试会按原有后台限额记账。

新增代码集中于 `gateway.py`、`attention.py`、`budget_policy.py`、`usage_accounting.py`，并增量接入 `gemini.py`、`store.py`、服务、管理路由与原生单页。部署只重建后端，NapCat 和 Drive OAuth 挂载保持原配置。
