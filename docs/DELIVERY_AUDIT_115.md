# v1.1.5：视频触发边界与执行审计

群聊的视频解析现在要求当前消息或同一批次的成员明确 @ 机器人。单发视频链接、昵称点名、引用机器人回复仍按普通群聊策略处理，不因此进入视频分支。私聊沿用准入规则；安全沙箱禁用视频解析。合批时优先保留真实 @ 触发，门卫和服务执行层均校验视频资格，符合条件后才解析视频目标或短链。

## 决策与投递关联

每个进入门卫的消息任务分配 `audit_id`，以 `job_id` 关联任务；成功生成后将标识写入加密 Outbox。审计保留门卫结果与原因，另记录执行状态及经过格式限制的原因码。

- 放行后显示 `processing`；入队后为 `queued`，投递中可显示 `sending`，最终根据实际结果显示 `sent`、`cancelled` 或 `uncertain`。
- 主模型弃权、下游拦截、追发重排、执行异常分别记录 `abstained`、`rejected`、`interrupted`、`failed`。发送前权限拦截或过期可显示 `blocked`、`expired`。
- 查询时由 jobs／Outbox 补全仍在处理中的记录。任务已完成但没有回复时可显示 `no_reply`，内部 job_id 不返回前端。
- 最近 30 条审计仍保存在加密主库，摘录脱敏，后台每 15 秒刷新。原有 `ignore`／`blocked` 决策不被执行状态回写覆盖。
- 管理沙盒使用相同关联流程；`source=sandbox` 下的成功状态表示预览完成，不表示真实 QQ 已发送。

上述执行状态独立于 ACK 入史和会话续链提交规则；撤回、清空、未知发送结果及过期仍按既有机制处理。

## 来源与输出筛查

来信继续使用运行时阈值，外部来源与生成输出使用独立安全阈值。两项安全概率先完整解析，达到阈值即拦截。对于来源／输出，置信度低于配置下限时，还需检查置信度是否低于 0.5，或 `1 - confidence` 是否达到该项阈值；满足任一条件则拒绝。字段缺失、非数值或越界仍拒绝，安全阈值本身没有放宽。

## 部署与回滚

沿用 `docker-compose.yml` 与 `compose.roaming-oauth.yaml`，后端继续只映射 `127.0.0.1:12141`。部署前备份环境文件、凭证和数据卷，并保留旧镜像；仅替换 `hakimi-bot`，让境内 NapCat 自动重连。既有 OAuth 只读挂载和命名数据卷继续使用。

本版没有新增数据库表；新增审计字段存放于既有加密 JSON 载荷，旧记录仍可读取。回滚优先使用保留的旧镜像，保留现有账本数据，避免恢复旧预算后重复消费。

完整结构见根目录 [HTML/CSS 架构图](../architecture.html)，GitHub 可直接阅读 README 中的 Mermaid 简图。
