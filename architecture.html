01部署与进程边界

当前默认拓扑 · OneBot v11 反向 WebSocket

兼容接入与部署依据 代码支持的其他入口，不代表默认公网开放

兼容 OneBot HTTP、正向 WS 和官方 QQ Webhook。HTTP 回调走 /webhooks/onebot 或 /webhooks/qq，分别验证 HMAC 或 Ed25519；默认 Nginx 模板只暴露反向 WS 路径。

反向 WS 验证 Bearer Token、Self-ID、Universal 角色，并经 get_login_info 再核对身份。连接可接管旧会话，带心跳和受控 RPC。

视频分支 · 03 → 05

B 站资料与原片分析

私聊／群真实 @→有效 BV→公开资料→来源筛查→分析

群聊要求当前消息或同批成员明确 @ 机器人；单发视频、昵称点名或引用回复不会开启视频分支。私聊沿用准入规则，安全沙箱禁用视频解析。

符合条件后才解析 BV／短链。优先元数据、字幕和公开材料；配置允许且需要视听信息时，走受限下载 → Files API → 视频分析。

原片不可用时可回退已审核的文字资料；预算与权限仍须有效。多视频取首个有效目标，无 BV 的观看意图回到聊天。

外部视频材料与分析摘要不写入聊天历史。

03分层筛查与投递审计

1.1.5 · 触发资格、模型判定与发送结果逐层关联

触发层 · 本地判断

先区分接话与看视频

普通用户的私聊、真实 @、顶层昵称点名与已验证引用可构成明确请求，安全放行后跳过自由插话门槛。未获 Owner 邀请的已知 Bot 即使 @ 本机，也必须通过自身接话阈值。

视频另经 can_watch_video 校验。群批次优先选择真实 @ 消息作为触发依据，避免合批时被昵称点名覆盖；视频链接本身不再构成明确请求。

attention.py · group_pipeline.py · service.py
筛查层 · Decisions

来信与来源／输出分别判断

来信使用运行时阈值；外部来源和生成输出继续使用独立安全阈值。两项安全概率均先解析，达到阈值立即拦截，缺失或畸形数据拒绝通过。

来源／输出的置信度低于配置下限时，再检查是否低于 0.5，或剩余概率质量是否可能触及阈值；任一满足则拒绝，避免仅因低于旧下限误拦有效结果。

GeminiGateway.screen · 筛查回归测试
观测层 · 鉴权后台

决策与执行结果并列显示

保留门卫的结果、原因、概率与置信度，另附 execution_status 与受限原因码。门卫放行后仍可能出现模型弃权、下游拦截、撤回取消或发送待确认。

主库加密保留最近 30 条，摘录脱敏；后台每 15 秒刷新。查询时用关联的 jobs／Outbox 状态补全未结束记录，内部 job_id 不返回前端。

B

相邻消息间隔达到 30 分钟时，按 BOT_TIMEZONE 标注时间断点。视觉简述追加为新行，图片字节不进入 B。

当轮动态尾窗

Owner 专属背景仅在对应私聊加载。可选记忆先让出预算；门卫输入与 C 尾窗默认分别以本地估算的 4,200 Token 限长。

最多 16 条／24,000 字；保留 event_id、发送者 ID、昵称与正文，引用回复可对应到被回应的那条消息。

多图仍补邻近文本
