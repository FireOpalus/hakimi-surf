03 / 部署结构

以仓库 Dockerfile、Compose 与 Nginx 模板为依据

境内协议端 → 境外主脑

境内 · NapCat⇄ WSS ⇄境外 · Nginx TLS⇄127.0.0.1:12141

境内使用 docker-compose.napcat.yml，可采用官方 Node 镜像覆盖模板；主动向境外建立反向 WSS。QQ 文件经 RPC／Base64 传递，两端不共享本地文件路径。

deploy/hakimi-ws.conf 只精确代理一条带随机后缀的 WS 路径，其余公网路径返回 404。WebUI 与后台分别经 SSH 隧道访问回环 6099／12141。

境外后端与数据边界

Uvicorn × 1+进程内 asyncio 任务+hakimi-data → /app/data

容器 UID 10001、只读根文件系统、持久卷与视频 tmpfs。WS 帧上限 16 MiB，Ping 25 秒／超时 30 秒；/healthz 检查任务存活，进程锁限制共享数据库。

两端 TZ 与后端 BOT_TIMEZONE 均使用 Asia/Shanghai。后端仍为单副本，NapCat 分离不等于业务横向扩容；旧同机／Webhook 模板仅用于另行选择的拓扑。

展开：消息处理路径 固定命令、模型回复与视频分支

普通消息 / 固定命令

  1. 协议认证与 Layer 0 准入后，在接收锁内 receive → 同会话引用／转发展开 → receive 更新，再由 Store.admit 写 jobs 与持久化防抖批次。
  2. Worker 领取任务并复检权限。固定命令由本地代码执行，直接写入 Outbox，无需模型生成。
  3. 对话锁覆盖读取最新会话历史、Decisions 输入筛查 → admit_history → Interactions 生成 → Decisions 输出筛查；按阶段检查 epoch。
  4. 解析 AT／MEME，普通文本回复先由 reply() 幂等入历史再入 Outbox；Delivery 复检后发送，确认的群文本更新公开索引，并可调度记忆压缩。

B 站链接 / 视频分析

  1. 消息筛查通过后解析 BV，读取公开视频元数据，并尝试取得公开字幕等资料。
  2. VideoWatch 对外部文字资料单独筛查；默认优先使用字幕与文字生成摘要。
  3. 原片功能开启且需要视听信息时，经额度与时长检查，进入 受限下载 → Files API → 视频筛查与生成；不可用时按实现回退文字资料。
  4. 来源链接由已验证 BV 生成，结果进入 Outbox；原始用户请求经门卫后可进入历史，但外部视频材料与生成摘要不写入聊天记忆。
