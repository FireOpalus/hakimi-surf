单位为秒，范围 0–30。消息连续到达时重新计时，但不超过最长等待；当前已开始生成的回复不受影响。普通群聊等待或最长等待设为 0 时，全场景关闭合并等待。命令仍即时处理。

请求限流与发送节奏

单用户与全局每分钟限流及待处理队列容量立即生效；超出限流的消息在入队前静默忽略。拟人发送延迟范围 0–10 秒，且最长延迟不得小于最短延迟。

图片尺寸与智能压缩

先按原图大小和总像素上限放宽接收，再在本地按 Lanczos 缩放为高清 JPEG 发给模型，编码目标 ≤800 KiB，复杂图片仍可能超过；常规／16:9 截图默认长边 ≤1600px、长截图默认 ≤2560px，长宽比 ＞4.5 的超长图在空余槽位充足时沿长轴自动切为两张带重叠的高清切片。

Decisions 来信阈值

提高注入／违规阈值会减少拦截，降低回应阈值会增加自由插话。外部来源与模型输出继续独立执行严格筛查；这些设置不改变白名单、身份或工具权限。

阈值如何作用于私聊、点名与外部 Bot

私聊与明确点名、回复机器人通过安全检查后可直接回应（群聊仅在明确 @ 机器人时解析视频）；外部 Bot 即使主动 @ 或引用回复也不会跳过门槛（默认 0.85，设为 1.00 为 0 Token 完全屏蔽；仅 Owner 发起 /bot-interact 时临时豁免 2 轮）。群内自由插话仍看 should_reply，每个群可在各自平台模块页（QQ / Telegram）中调整触发策略与活跃度预设；Owner 普通群聊的插话门槛最高为 0.28。

外部 Bot 防互刷与回复阈值

    
已知 Bot 在群聊按 should_reply 回复阈值控制触发（默认 0.85，设为 1.00 即 0 Token 完全屏蔽），即使外部 Bot 主动 @ 或引用哈基米也不跳过阈值；未邀请的 Bot 回复不会带出 @ 或引用锚点。私聊始终忽略；Owner 和机器人自身不能加入。此名单与「讨厌鬼小黑屋」分别维护。
